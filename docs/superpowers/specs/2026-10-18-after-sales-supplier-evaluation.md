# 售后问题登记表：供应商评价

日期：2026-10-18

## 背景

供应商评价里已有一条来自金蝶检验单的到货合格率。售后问题登记表是另一条线，记录已经发生的市场客诉，评价对象是表里的厂家。

两条线并列展示。售后结果不写入检验单的合格率，也不做加权扣分。

## 产物

上传一份 `.xlsx` 后，得到一张汇总表和左右两张图。

表的列顺序固定为：

| 列                 | 含义                                             |
| ------------------ | ------------------------------------------------ |
| 供应商             | 厂家全称                                         |
| 客诉事件（个）     | 归到该供应商的数据行数                           |
| 产品问题数量（个） | 这些行的「数量（个）」合计                       |
| 产品问题概括       | 各大类的事件数，如「设备包装 5个、异物问题 1个」 |
| 结案情况           | 已结案件数与待跟进件数                           |
| 我司赔付金额       | 「我司赔付金额」合计                             |
| 工厂赔付金额       | 「厂家赔付金额」合计                             |
| 工厂赔付率%        | 工厂赔付金额 ÷ 我司赔付金额                      |

左图是饼图，按各供应商工厂赔付金额从大到小。右图是条形图，按各供应商客诉事件个数从多到少。

## 文件约定

- 读取第一个工作表。
- 第 1 行是标题，不参与解析。
- 表头在第 2 行。数据从第 3 行读到最后一行。
- 按表头文字找列，不按列号。必读列是：厂家、数量（个）、处理方案、我司赔付金额、厂家赔付金额、产品问题大类。
- 整行都空则跳过。

以下列不进入汇总：反馈人、渠道/平台、经销商、产品名称、口味/规格、ERP商品编码、商品条码、生产日期、商品大类、问题描述、备注、问题凭证、产品问题具体、责任判定、其他情况内容补充描述、平台/店铺、买家账号，以及名称带「历史字段」的列。经销商是反馈来源，不是供应商。

## 解析

每一行非空数据是一条客诉事件。单元格里用换行写了多个商品时，仍算一条事件，不拆成多条。

**供应商。** 取「厂家」。去掉首尾空白和换行。末尾的 `XLS` 去掉后再分组、再展示。`禾胜禾（福建）食品有限公司XLS` 与带换行的同一名称归为同一供应商。

**数量。** 「数量（个）」转成数字。单元格里有多行数字时，把这些数字相加。只有一个数字时只计一次。空、`-`、`—`、`/` 视为数量缺失：这条事件仍计数，数量加 0。

**金额。** 「我司赔付金额」「厂家赔付金额」各自转成数字，一行各计一次。空值不当成 0 元，汇总时跳过。千分位逗号先去掉再转换。

**问题大类。** 取「产品问题大类」的第一段非空文字，一行只归一个大类。

**结案。** 「处理方案」为「待跟进」的是待跟进，其余方案（包括「退货退款」）是已结案。

## 汇总

按供应商分组后：

- 客诉事件（个）= 行数。
- 产品问题数量（个）= 各行数量之和。数量缺失的行不增加这个合计数。
- 产品问题概括 = 各大类的行数，格式为「大类 n个」，大类之间用顿号连接，个数多的在前。个数相同则按大类名称排序。
- 结案情况 = 「已结案 a个，待跟进 b个」。a + b 等于客诉事件个数。
- 我司赔付金额、工厂赔付金额 = 各行已填写金额之和。该供应商两列都没有任何已填金额时，两列都显示「—」，不显示 0。
- 工厂赔付率% = 工厂赔付金额 ÷ 我司赔付金额，显示为保留两位小数的百分数，例如 `100.00%`。我司赔付金额没有已填数字，或合计为 0 时，赔付率显示「—」。只对已填金额做除法，空金额不参与分子或分母。

表格按工厂赔付金额从大到小排。没有工厂赔付金额的供应商排在最后。金额相同则按客诉事件从多到少排。

图表里的供应商用简称，表格里用全称。简称的做法：去掉末尾 `XLS`、括号及括号中的文字、结尾的「食品有限公司」「生物科技有限公司」「有限公司」，再去掉开头以「省」或「市」结尾的地名。按这个规则仍带地名、且本表已经用过的简称固定为：临沂宏旭、乡村爱情、云吉、美致。新供应商套用同一规则；套完仍不适合当轴标签时，图表改用全称。
