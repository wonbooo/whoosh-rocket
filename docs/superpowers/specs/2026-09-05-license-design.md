# 咻咻小火箭授权（License）设计

日期：2026-09-05

## 背景

桌面端（Tauri）需要先导入有效 license 才能使用。签发人用同一应用内的口令打开生成页，手动填写对方机器码，生成只能用 3 个月、绑定该机器码的 license，再交给对方导入。

## 目标

- 未授权：不能连接金蝶、不能下单，只能看本机机器码并导入授权。
- 已授权：正常使用；标题栏可见到期日。
- 签发：输入口令后打开生成页；机器码由签发人填写；有效期从**签发当天**起 3 个月。
- 换电脑、改文件、过期均失效。

## 非目标

- 不做联网授权服务器。
- 不防专业破解（安装包内含加密私钥，知道口令即可签发）。口令只挡住普通用户。
- 纯浏览器 `vite` 开发不强制授权（无 Tauri 则跳过闸门），避免挡住日常前端开发。

## 架构

```
启动 → Rust 读本机机器码 + 本地 license 文件 → 验签/比对/过期
         ├ 无效 → 全屏授权页（机器码、导入、口令签发）
         └ 有效 → 首页；标题栏显示到期日；仍可用口令打开签发页
```

- **校验与签发在 Rust**，前端只展示和调用命令。
- **公钥**编译进应用，只用于验签。
- **私钥**用签发口令加密后编译进应用；口令正确才解密并签发。
- 签发人在生成页**手动输入**目标机器码，不自动填本机码（本机码仍展示在授权页，方便用户抄给签发人）。

## License 格式

明文 JSON，再整体做 Ed25519 签名。导入可用 `.lic` 文件或粘贴同一段文本。

```json
{
  "v": 1,
  "machineId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "issuedAt": "2026-09-05",
  "expiresAt": "2026-12-05",
  "sig": "<base64 签名>"
}
```

- `issuedAt`：签发日（本机日历日，`YYYY-MM-DD`）。
- `expiresAt`：`issuedAt` 加 3 个日历月（例：2026-09-05 → 2026-12-05）。
- 签名范围：除 `sig` 外的字段，按固定字段顺序拼接后签名，避免 JSON 键序问题。
- 本地保存路径：Tauri 应用数据目录下的 `license.lic`。

## 机器码

Windows：读取 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`。  
其它系统（测试/异常）：退化到稳定主机标识，并在界面标明。

授权页提供「复制机器码」。

## 命令（Tauri）

| 命令                 | 作用                                                |
| -------------------- | --------------------------------------------------- |
| `get_machine_id`     | 返回本机机器码                                      |
| `get_license_status` | `{ valid, machineId, expiresAt, reason }`           |
| `import_license`     | 校验文本/文件内容后写入 `license.lic`               |
| `issue_license`      | 口令 + 对方机器码 → 生成 license 文本（不写入本机） |

`issue_license` 成功才算口令正确；口令错误返回明确错误，不进入生成结果。

## 界面

- **未授权全屏页**：本机机器码、复制、选择 `.lic` / 粘贴导入、错误原因。
- **已授权**：现有首页与下单流程不变；标题栏展示「授权至 YYYY-MM-DD」。
- **签发页**（未授权、已授权均可）：先入口令；通过后输入对方机器码，生成文本，支持复制和另存为 `.lic`。

## 错误文案

| 情况          | 文案                   |
| ------------- | ---------------------- |
| 未导入        | 请先导入授权           |
| 过期          | 授权已过期，请重新签发 |
| 机器码不符    | 授权与本机机器码不匹配 |
| 签名/格式损坏 | 授权文件无效           |
| 口令错误      | 签发口令不正确         |

## 测试

- 签发：到期日 = 签发日 + 3 个月；签名可被公钥验证。
- 校验：本机码一致且未过期 → 通过；过期 / 错机器码 / 改字段 → 失败。
- 导入：合法文本写入后 `get_license_status.valid === true`。
- 前端：未授权时首页下单入口不可用（闸门拦截）。

## 签发口令

实现前由你提供一个签发口令。用该口令加密私钥后提交到仓库；口令本身不要明文写进仓库。更换口令需要重新加密私钥并发新安装包。
